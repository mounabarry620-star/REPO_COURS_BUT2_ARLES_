1. Introduction & Objectifs Pédagogiques

Le TP n°4 aborde un cap fondamental de la programmation en Java : l'interaction avec le système de fichiers et la persistance des objets (sauvegarder l'état des données entre deux exécutions du programme). Ce travail pratique est scindé en deux exercices complémentaires :

  • Exercice 1 (Exploration et métadonnées de fichiers) : Apprendre à inspecter un répertoire passé en argument de ligne de commande (args[0]), instancier un objet java.io.File, lister son contenu via list(), identifier les sous-dossiers et fichiers via isDirectory(), mesurer les tailles en octets avec length(), et réaliser un tri alphabétique insensible à la casse avec Arrays.sort(tableau, String.CASE_INSENSITIVE_ORDER).
  • Exercice 2 (Gestion bancaire et persistance par sérialisation) : Concevoir un système orienté objet composé d'une classe Compte et d'une classe Banque (encapsulant une ArrayList<Compte>). Rendre ces classes sérialisables via l'interface java.io.Serializable afin d'écrire et de relire l'état complet de la banque dans un fichier binaire avec ObjectOutputStream et ObjectInputStream, tout en sécurisant les opérations grâce à try / catch (gestion des exceptions IOException et ClassNotFoundException).

4.1 Exercice 1 : ListerRepertoire.java

Références de cours : Chapitre 9 (Slide 17, 18, 19, 21), Chapitre 5 (Tableaux), Chapitre 10 (Exceptions d'indices).

L'objectif de cette classe est d'agir comme une commande système équivalente à ls -l ou dir. Le programme s'articule autour des étapes logiques suivantes :

  1. Validation des arguments : Si args.length == 0, l'utilisateur a oublié le répertoire. On affiche un guide d'utilisation (Usage) et on quitte proprement sans lever de ArrayIndexOutOfBoundsException (Chapitre 10, slide 7).
  2. Instanciation logique de la ressource : File repertoire = new File(args[0]); (Chapitre 9, slide 21).
  3. Contrôles physiques :
    • repertoire.exists() : s'assure que le dossier est physiquement présent sur le disque (Chapitre 9, slide 18).
    • repertoire.isDirectory() : s'assure qu'il s'agit bien d'un dossier et non d'un simple fichier.
  4. Extraction et tri des noms : String[] listeFichiers = repertoire.list(); extrait les noms (Chapitre 9, slide 21). Puis Arrays.sort(listeFichiers, String.CASE_INSENSITIVE_ORDER); ordonne le tableau sans tenir compte de la casse (Énoncé TP4).
  5. Parcours et bilan statistique : Une boucle for classique (Chapitre 5, slide 5) inspecte chaque élément via un sous-objet new File(repertoire, nom) pour afficher son type ([Répertoire] ou Fichier), mesurer sa taille via element.length() (Chapitre 9, slide 19) et cumuler la taille totale. 
public class ListerRepertoire {
    public static void main(String[] args) {
        if (args.length == 0) {
            System.out.println("Erreur : Aucun répertoire spécifié.");
            return;
        }

        File repertoire = new File(args[0]);
        if (!repertoire.exists() || !repertoire.isDirectory()) {
            System.out.println("Erreur : Chemin invalide ou inexistant.");
            return;
        }

        String[] listeFichiers = repertoire.list();
        Arrays.sort(listeFichiers, String.CASE_INSENSITIVE_ORDER);

    }
}

4.2 Exercice 2 (Q1) : Compte.java

Références de cours : Chapitre 3 (Slide 2, 3, 8, 10 - Encapsulation, Constructeur, Getters/Setters), Chapitre 9 (Slide 24-25 - Serializable).

La classe Compte modélise l'entité atomique du domaine bancaire :

  • Encapsulation : Les variables d'instance proprietaire (String) et solde (double) sont strictement déclarées private (Chapitre 3, slide 2).
  • Interface Serializable : En ajoutant implements Serializable (du package java.io), nous autorisons la machine virtuelle Java à convertir l'état complet d'un compte sous forme d'un flux d'octets sans avoir à coder d'écriture manuelle champ par champ (Chapitre 9, slide 24-25).
  • Constructeur & Méthodes : Fournit un constructeur à deux paramètres, les accesseurs/mutateurs conformes, ainsi qu'une méthode afficher() (Chapitre 3, slide 10).
import java.io.Serializable;

public class Compte implements Serializable {
    private static final long serialVersionUID = 1L;
    private String proprietaire;
    private double solde;

    public Compte(String proprietaire, double solde) {
        this.proprietaire = proprietaire;
        this.solde = solde;
    }

    public String getProprietaire() { return this.proprietaire; }
    public void setProprietaire(String proprietaire) { this.proprietaire = proprietaire; }
    public double getSolde() { return this.solde; }
    public void setSolde(double solde) { this.solde = solde; }

    public void afficher() {
        System.out.println("Titulaire : " + this.proprietaire + " | Solde : " + this.solde + " €");
    }
}

4.3 Exercice 2 (Q2) : Banque.java

Références de cours : Chapitre 6 (Slide 2, 7-10 - ArrayList), Chapitre 9 (Slide 23-29 - Sérialisation d'objets composés), Chapitre 10 (Slide 5-8, 14-17 - Gestion des exceptions try/catch).

La classe Banque joue le rôle de conteneur d'agrégation :

  • Gestion dynamique des comptes : Elle utilise un ArrayList<Compte> (Chapitre 6), initialisé dans le constructeur via new ArrayList<Compte>().
  • Sérialisation en cascade : Parce que Banque et Compte implémentent tous deux Serializable, la sérialisation de l'objet Banque sérialise automatiquement toute la liste des comptes contenus à l'intérieur ! C'est exactement le cas d'école présenté dans le cours de M. Thon avec la classe Classe_etudiants (Chapitre 9, slide 26).
  • Méthode sauvegarder(String nomFichier) : Utilise ObjectOutputStream enrobant un FileOutputStream (Chapitre 9, slide 28). L'appel fWo.writeObject(this); écrit l'objet entier. En cas de problème disque, une IOException est capturée par le bloc try / catch (Chapitre 10, slide 16).
  • Méthode charger(String nomFichier) : Vérifie d'abord fichier.exists() (Chapitre 9, slide 18). Si oui, ouvre un ObjectInputStream(new FileInputStream(f)) (Chapitre 9, slide 29), désérialise avec readObject(), et transtype en (Banque). Les exceptions IOException et ClassNotFoundException sont gérées proprement. 
public boolean sauvegarder(String nomFichier) {
    try {
        ObjectOutputStream fWo = new ObjectOutputStream(new FileOutputStream(nomFichier));
        fWo.writeObject(this);
        fWo.close();
        return true;
    } catch (IOException e) {
        System.out.println("Erreur lors de la sauvegarde : " + e.getMessage());
        return false;
    }
}

public static Banque charger(String nomFichier) {
    File f = new File(nomFichier);
    if (!f.exists()) {
        System.out.println("Erreur : Le fichier \"" + nomFichier + "\" n'existe pas.");
        return null;
    }
    try {
        ObjectInputStream fRo = new ObjectInputStream(new FileInputStream(f));
        Banque b = (Banque) fRo.readObject();
        fRo.close();
        return b;
    } catch (IOException | ClassNotFoundException e) {
        System.out.println("Erreur chargement : " + e.getMessage());
        return null;
    }
}

4.4 Exercice 2 (Q3) : Principal.java

Références de cours : Chapitre 2 (Slide 18-20, 22-25 - Menu do/while, switch, Scanner).

La classe Principal contient le point d'entrée exécutable main. Elle gère le cycle de vie de l'application via un menu textuel interactif :

  • Boucle interactive : do { ... } while (choix != 6); garantit l'affichage répété du menu jusqu'à ce que l'utilisateur choisisse explicitement de quitter.
  • Robustesse de la saisie utilisateur : La saisie du montant utilise Double.parseDouble(...) (Chapitre 7, slide 1) entourée d'un try / catch (NumberFormatException) (Chapitre 10) et accepte aussi bien le point que la virgule décimale, évitant ainsi les plantages de saisie console.
  • Test de persistance réel : L'utilisateur peut créer des comptes, les sauvegarder dans un fichier (ex: banque.dat), quitter l'application, la relancer et recharger ce même fichier pour constater la restauration intégrale des données.

6. Bilan Pédagogique & Bonnes Pratiques de Qualité

Synthèse des acquis du TP n°4
  • Zéro code hors-programme : Ni streams lambdas ni bibliothèques tierces. Toutes les fonctionnalités reposent sur les API standard du cours (java.io.File, ObjectInputStream, ObjectOutputStream, ArrayList).
  • Encapsulation respectée : Données membres privées, constructeurs dédiés, getters et setters rigoureusement implémentés.
  • Sérialisation déclarative : La mise en œuvre de implements Serializable démontre l'élégance de Java pour persister des graphes d'objets complexes sans aucun parseur manuel.
  • Programmation défensive : Contrôles systématiques de l'existence des fichiers avant lecture (exists()) et capture explicite des exceptions IOException et ClassNotFoundException pour empêcher les arrêts inopinés du programme.
